# FLOORS, NOT RANGES -- this cost a failed build. An upper bound lets pip backtrack into
# releases that predate Python 3.12 and ship no cp312 wheels: `pandas>=2.0,<2.3` resolved
# to pandas 2.1.0 (Aug 2023), and since python:3.12-slim carries no C compiler, pip tried
# to build it from source and the image died on `Unknown compiler(s): [cc, gcc, clang...]`.
# A floor keeps the resolver on recent wheels. Only pin an upper bound against a KNOWN
# incompatibility, never as a vague precaution.
pandas>=2.2,<3
numpy>=1.26
#
# The <3 ceiling IS a known incompatibility, not a precaution. Without it this resolved to
# pandas 3.0.5, which removed DataFrame.fillna(method=...) -- used on every request in
# enrich_with_indicators. The image would have built perfectly and then raised TypeError on
# every analyze. Those calls are now .bfill()/.ffill(), which work on both, but pandas 3
# also flips copy-on-write and the default string dtype, and none of that has been
# validated here. Lift the ceiling deliberately, after testing, not by deleting it.

# pandas-ta is deliberately NOT here. It is an abandoned 2021 beta (0.3.14b0) that still
# does `from numpy import NaN`, removed in numpy 2.0, so it silently failed to import on
# any modern build -- and indicators.py's fallback for that hardcoded ADX_9 = 25.0, which
# made its own `adx > 25` gate permanently False. Rather than pin numpy below 2 to keep a
# dead dependency alive, the Wilder ADX/ATR/RSI in indicators.py replaces it outright and
# is checked against a dependency-free reference by indicators_test.py to ~1e-14. Dropping
# it also removes the numpy ceiling that forced the source build above.

# mistake above. To lift it: load every trained_models/*.joblib under the newer version
# first, then move the pin.
